# AI Composer Agent — 下一轮试听实验与随机化灵感系统（2026-10-24，提案 + 已实现薄切片）

> 状态说明：B、C 的试听反馈是用户报告的定性反馈；尚无匿名评分明细、独立模型重复试验或统计显著性结果。本文件将产品建议与工程实现严格分开。用户正式已批准的 D-005（仅通用 LLM 负责 AI 作曲）、D-006/D-007（MCP First，候选审批）保持不变。

## 1. 基线诊断

- B（原始来源风格标签 `blues/shuffle`）和 C（来源标签 + 参考 MIDI 的节奏时值、力度等统计特征）获得相对较好的试听反馈，说明二者值得继续优化，**不能得出 C 比 B 更优秀**或“参考库已经证明有效”的结论。
- 先前 A/B/C 的 3 首曲目由**同一个 GPT-6 会话**共同构思，节奏、密度、力度以及声部内容一起变化。该实验已建立可试听的技术基线，但缺乏独立生成的因果证据。
- 仓库已在 composition 包中实现 SeededArranger、seeded variants、局部生成候选、单轨混配。这些用于确定性规则演示或候选变化；**与新的随机创作灵感规划不是同一层**。不得再添加一个替代 LLM 的作曲引擎。

## 2. 下一轮实验：四个相互隔离的创作条件

| 臂 | 给外部通用 LLM 的内容 | 检验问题 |
|---|---|---|
| A（必要对照） | 共同硬约束，不给 MIDI 来源标签、数据或灵感 | 与无参考相比是否有差异 |
| B（已有积极反馈） | A + 经过标注的来源风格文字，例如 `blues/shuffle` | 风格标签是否有价值 |
| C（已有积极反馈） | B + 权利可追溯的 MIDI 参考统计（来源声明 ≠ 专家验证） | 特征证据是否有边际收益 |
| D（本阶段重点） | C + **用户显式启用**的种子化灵感牌（原创提示，不复制 MIDI） | 受控随机创意能否在满足硬约束的同时提升新颖度 |

先试跑 **3 个题目 × 4 条条件 × 2 个独立随机种子 = 24 个作品**。生成时每个样本使用新的 LLM 上下文，不允许复用另一实验条件的信息；同一题目的旋律长短、目标调式/拍号、功能声部、音色库、预算（模型/温度/Token）及最终统一响度应保持可比。将方案、样本 SHA、模型版本、实际上下文、MCP 参数、请求响应、时间、成本以及失败率写入不可混淆的审计记录。用户听评前用随机编码隐藏组别。

三个测试任务建议：
1. **4/4、D Dorian、Shuffle / 16 小节四轨**：复用最成熟的 B/C 反馈基线，检验律动自然度与调式中心；参考音乐录制者不足，应标明限制。
2. **3/4、舒缓游戏场景 / 8–16 小节**：以曲式留白、动机与力度为主，避免只研究鼓组音乐。
3. **4/4、紧张游戏战斗 / 16 小节**：检验重复段落、能量曲线和配器分工；参考 Chiptune 的游戏用途不代表严格流派。必要时根据引入的可信 MIDI 源进一步分层。

只有 P0 流程稳定后才扩展到 **6 个任务 × 4 臂 × 2 次 = 48 个生成样本**。6/8、12/8 等薄弱拍号暂不与覆盖充分的参考条件直接比较，先补版权可靠且不同演奏者的来源。

### 两层不同的验收

**机器门槛**：MCP 连接/会话/调用身份，MIDI 完整性、轨道锁、音符范围、音级集合、硬节奏规则、Music Core 干跑、revision 不变、原始许可证/来源保留。失败计入各条件的失败率，**不只比较成功的作品**。

**人工听评**：建议至少 5–8 名独立听者，随机匿名次序，分别评价四个维度：① 节奏/律动自然度，② 主旋律/调式辨识度，③ 声部融合和层次，④ 动机创新与音乐完整性；可记录场景适配、偏好排序和评论。做同题目内配对比较，展示评分分布、样本数量和反例。盲听反馈“B/C 更好”不能自动推断概率置信区间或统计显著性。人工体验门槛是设计候选，未由用户最终批准。

## 3. 随机化不等于随机音符

提出六种**可组合且可审核**的灵感分面，先作为外部 LLM 的可选**软指令**，不能擅自修改既定 MusicProject：

| 分面 | 示例创意 | 防失控条件 |
|---|---|---|
| 节奏 Rhythm | 弱起问答、错拍回应、留白、复拍内部交错 | 严守用户拍号，用户声明的严格律动只由实际音符检验 |
| 动机 Motif | 主题碎片重组、问答、特征音程重复 | 保留辨识度，不越过锁定音符或重写禁区 |
| 调式色彩 Harmony | 特色音突出、音阶内持续音、悬置与解决 | 区分主音中心与纯音级集合；不无许可加入调外音 |
| 声部分工 Texture | register contrast、声部接力、减法配器 | 只能编辑授权轨道，其他声部只读；单轨时过滤跨轨要求 |
| 曲式 Form | 三加一变化、提前再现、短暂减密度 | 必须有足够小节，不能为了花样改掉要求的段落结构 |
| 演奏表现 Expression | 力度弧线、句末呼吸、单次反差 | 必须有句法动机，避免乱抖 Velocity 和机械人性化 |

### 创意预算

- **Subtle 保守**：抽 2 张、低强度、强调风格保真与可听性。
- **Balanced 均衡（首推）**：抽 3 张、允许中等冲突与反差的音乐想法，但不改变硬约束。
- **Adventurous 冒险**：抽 4 张、允许更激进的动机碎片化和密度反转，仍不得直接编辑工程。
- **按需聚焦**：选择若干分面，如 rhythm + motif；不足时只抽可用分面，不凑数、不自动引入其他维度。

设计上还预留以下后续方案，但此次**未实现**：

1. **受约束音符变奏**：对已获授权的选区提供“不动音高，仅改节奏”或“保留节奏，仅改音高”的随机变体，再统一 Music Core 检验；这是用户主动选择的候选编辑，不作为新作曲模型。
2. **参考风格交叉**：分别从不同版权允许的数据源提取一个 Rhythm 和一个 Texture 特征，通过通用 LLM 综合，附上每个来源的授权和置信度；不拼接或复制第三方旋律。
3. **音乐矛盾卡**：如“保持稳定节拍，同时在第四小节制造一次意外停顿”。先检测冲突，不允许两张语义自相矛盾的卡同抽。
4. **奇遇链/多轮创意**：同一乐句选择保留一张灵感卡、重抽其余张；保留审计身份与子种子以便撤销和对照。
5. **概率性演奏变化**：可参考成熟 MIDI 软件 Note Chance / Velocity Chance 的思想，但必须显式开启、锁定允许变动的音符集合、避免每次回放结果不同影响对照；将来需要稳定、可导出的 MIDI 实现。

## 4. 本 PR 的工程薄切片（实施后以 GitHub CI 为准）

- `packages/composition/src/planning/inspiration.ts`：`drawMusicalInspiration` 是纯函数，固定 `musical-inspiration-v1` 版本，uint32 seed，经候选的 meter / groove / scopeBars / editableOtherTracks 筛选，以独立排序得出原创提示卡；不调用模型，不读取网络或全局随机源。
- `services/agent-api/src/mcp/composition-guide.ts`：`music.draw_inspiration` 是需要授权快照和未锁定轨道的只读 MCP Tool。现有 `music.prepare_composition_brief` 只有收到 `inspirationSeed` 才会附上相同灵感包；旧调用保持不变。
- 来源与许可：随机提示词为新写的通用音乐建议，**不复制 Oblique Strategies 或 MIDI 原曲**。现有参考库的 CC BY 4.0 / CC0 / Public Domain 授权由参考检索工具维持。
- 输出携带 `seed` / `algorithm` / `cards[].id` / `level` 和用户声明的目标环境。系统只对“相同输入抽到同一提示”负责；不保证外部 LLM 以相同 seed 重现相同音符。
- 禁止在无用户选择情况下自动 reroll，或将音乐建议偷偷转为用户硬规则。除音符有效性外，不能声称“灵感分数”和音乐质量具有单调关系。

### 示例调用

```json
{
  "name": "music.draw_inspiration",
  "arguments": {
    "sessionId": "<由 music.open_snapshot 返回>",
    "trackId": "melody",
    "seed": 19501,
    "level": "balanced",
    "tonic": 2,
    "mode": "dorian",
    "meter": "4/4",
    "groove": "shuffle",
    "startTick": 0,
    "endTick": 7680,
    "focus": ["rhythm", "motif", "harmony", "texture", "form", "expression"]
  }
}
```

另可调用原有 `music.prepare_composition_brief` 并添加 `inspirationSeed:19501`、`inspirationLevel:"balanced"`。若未传入 seed，则不产生随机建议。新 API 结果依然显示 `approved:false`、`applied:false`，永不伪造浏览器工程已被修改。

## 5. 后续工程依赖与推进次序

| 里程碑 | 核心任务 | 可量化验收 |

| P0（当前） | 种子化创意、参数校验、MCP 只读抽卡、无自动改写 | 1–4 张合法不同维度的卡、同种子复现、锁/失效会话拒绝、工程 revision 不动 |

| P2 | 浏览器 MusicProject 授权会话/预览/批准/撤销全闭环 | 项目与 MCP 双向状态一致，锁、revision、撤销真实端到端验收 |
