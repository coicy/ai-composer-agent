# 可解释编配诊断 v0.1（仅启发式）

本功能是“音乐设计质量辅助”，与现有 **MIDI 数据合法性硬约束** 严格分离。

## 分析管线
1. 以主旋律选中 Tick 范围内的**实际重叠时长**构建 12 个 pitch-class 权重。
2. 对 12 个根音 × 大/自然小调进行音阶覆盖度比较，并报告最多 3 个调性**假设**。音符过少或候选接近时给出“证据不足/歧义”，不得断言真实调性。
3. 在连续 4/4 窗口内，将主旋律音高类别与大/小/减三和弦比对，输出一个暂定和弦名称或“信息不足”。这是**旋律音符的可能和弦匹配**，不等价于作品真实和声分析；暂不支持转位、属七和弦、调式借用、爵士和声等。
4. 在模型生成三轨候选后，基于实际音符时间重叠检查：
   - 低音比同时发声的主旋律高或同音；
   - 低音超出示例参考音域 MIDI 28–60；
   - 新轨道相邻起音跳进超过 12 半音；
   - 同时发声的和声与低音音域交叉；
   - 旋律与和声同时发声时，高比例的特定音程类别 1/2/6/10/11（**只视作可能的张力**，不能视为错误）。

输出确定性的计数和解释，不输出没有实证标定的“85 分音乐质量”等伪精确评级。零条提醒不等于好听；有提醒也不自动拒绝。

## Provider 如何使用
`proposeArrangement` 在 `ArrangementContext` 附上 `tonalProfile` 和 `chordSuggestions`。模型 Provider 只能将这些假设作为参考，不得将它们当强制调性；建议首先尊重用户的风格说明。真正的安全硬约束仍仅涉及输出结构、合法音高、时间范围、容量、角色数量和用户确认。

`ArrangementCandidate.assessment` 附带音调/和弦分析、结构统计、提醒及免责声明。在网页编配候选审核区可以查看；输出随原 ChangeSet 一起被拒绝、取消或确认。并不修改原工程音符，也不需改变 Music Core 的 Schema。

## 后续必须完成
- 有标注的 MIDI 乐曲与人工听评基准，验证调性识别是否可靠；目前状态是**启发式实验**。
- 音乐理论约束选择：允许用户设置“强约束”或“风格性偏好”，而不是统一施加硬性规则。
- 多声部同刻和弦识别、和弦外音解决、对位与声部平行五度/八度、低音走向、更完整的和声功能与调式系统。
- 真实乐器音色和音频试听评估；现在只是固定 120 BPM 的 Web Audio 合成试听。

验证：`pnpm --filter @ai-composer/composition test`，以及 CI 中 Chromium Playwright 浏览器审批预览测试。真实模型作曲质量未验证。
