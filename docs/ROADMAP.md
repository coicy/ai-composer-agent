# 开发路线图与验收（规划）

M0 项目引导：脚手架、类型检查、测试、CI、文档；验收：本地可启动空白页面、CI 可运行。
M1 Music Core：tick/tempo/track/note、命令执行、锁、revision、diff、undo；验收：纯函数测试覆盖原子性、重复提交和陈旧版本拒绝。
M2 Piano Roll：网格、音符可视化和新增/拖拽/改时值/删除，键盘编辑、选择/缩放；验收：人工操作与保存重载一致。
M3 Playback + MIDI：试听、Transport、静音/独奏、SMF 导入导出；验收：多轨样例同步播放；明示 MIDI 不可表达的字段。
M4 Composition Agent：自主生成 4–16 小节旋律、不同候选、人工修改后续写、局部重写、和声/低音、ghost preview、确认/回滚；验收：在 UI 演示全部创作闭环。

## 端到端验收场景
输入“G 大调、6/8、8 小节奇幻冒险主题”→ 至少两版可编辑音符候选 → 选中第一版 → 手工修改第 3 小节 → 锁定第 1–4 小节 → Agent 续写第 5–8 小节且不碰锁定部分 → 预览对比 → 应用与撤销 → 加低音轨 → 试听 → JSON 和 MIDI 导出。

质量门槛：功能验收为确定性检查；音乐质量以有固定评分维度的人工听评结果单独报告。尚无通过的测试或性能基线。

## 双接入产品需求（D-006，已批准但未实现）

必须支持外部 Agent **经 MCP 调用本工具**，和用户**在工具内填写 LLM API 地址及 Key** 后内部调用通用 LLM。当前仅有环境变量配置的 OpenAI 调用原型，未交付 MCP Server 与 UI 内 API/Key 配置，不能以此充当双模式验收。工程规范、待裁决细节与建议任务见 [LLM_ACCESS_MODES.md](LLM_ACCESS_MODES.md)。

**候选实施顺序（尚未定优先级）**：凭据会话与地址安全 -> UI API/Key 配置 -> MCP 授权只读/候选工具 -> 当前浏览器 MusicProject 会话桥接及预览 -> 跨入口一致性与 E2E。所有工作遵守 D-005 和 Music Core 约束。

## D-007 已批准的实施顺序（覆盖 D-006 的并行建议）

**MCP First**：当前开发阶段优先交付独立 MCP 客户端可连接的工具入口、授权读取当前浏览器 MusicProject、生成/提交合法 MIDI 候选、UI 预览与人工批准/撤销。**内部 API 地址/Key 输入、凭据管理、多 Provider 配置全部后置**，不阻塞 MCP 首版。现有 OPENAI_API_KEY 原型仅作兼容，不属于 MCP 首版验收要求。MCP 完整闭环验收之后再规划内部 API 模式。
