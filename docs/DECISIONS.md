# 产品裁决与开放问题

## Accepted（用户已明确）
- D-001：产品为浏览器端轻量级自主作曲与辅助编曲 Agent。
- D-002：Agent 能从零写出真实旋律音符，并可续写/配器。
- D-003：用户必须直接编辑 Agent 创作结果。
- D-004：以钢琴卷帘为主编辑模式，**不使用五线谱**。
- D-005（2026-10-22，用户明确裁决）：**所有 AI 音乐创作与编曲由大语言模型（LLM）生成可编辑的 MIDI 音符和候选，不引入专用音乐生成模型及其预训练权重**（例如 MIDI-GPT），也不安排专用音乐模型的 Provider、sidecar 或 PoC 接入。允许确定性音乐理论分析、音乐指标、MIDI 编辑、音色合成与离线规则测试，它们不是替代 LLM 的 AI 生成模型。Music Core 校验、授权范围、候选预览、人工批准和撤销不变。
- D-006（2026-10-22，用户明确裁决）：**LLM 接入采用双模式**：① 外部 Agent 通过 **MCP** 调用本工具的音乐能力；② 用户在工具内输入/配置 **LLM API 地址与 API Key**，由本工具内部调用大语言模型。两条路径均必须遵守 D-005、Music Core 的范围/锁/版本校验、候选预览、用户显式批准和撤销；密钥不得泄漏至 MCP、工程文件、代码及日志。具体会话、MCP Tool、凭据存储与部署方案待工程评审。见 [LLM_ACCESS_MODES.md](LLM_ACCESS_MODES.md)。

## Proposed（设计方案，未获用户明确裁决）
- P-001：工程统一 JSON 数据源，MIDI 用作互操作格式。
- P-002：模型修改前需预览与人工确认，保护锁定范围。
- P-003：MVP 长度 4–16 小节，至少两个候选。
- P-004：TypeScript + React + Canvas，Tone.js 与 @tonejs/midi，服务器可选。
- P-005：采用 monorepo packages/apps 分层。
- P-006：480 PPQ 作为内部初始候选。

## Open
MCP 协议传输和会话绑定、内部 API/Key 会话与保存策略、LLM 服务商/型号及 API 部署与成本；商业/开源许可证；移动端支持程度；和声/节奏吸附默认值；初期音源和乐器集；协同编辑；候选数量与长度的最终产品批准。

变更 Accepted 需要用户明确授权，避免把建议伪装为既定规则。
